# 通过长桥模拟账户交易

[English](longbridge.md)

组合可以由 hone-quant 自己的模拟撮合交易（默认），也可以**连接长桥（Longbridge）模拟交易账户**。连接后的组合沿用同样的策略、计划时间、复核窗口和人工干预，但订单发送到长桥，账目以券商为准：每笔成交、现金和持仓都来自长桥的回报。hone-quant 通过开源的 [`longbridge` 命令行客户端](https://github.com/longbridge/longbridge-terminal)（longbridge-terminal 0.30 及以上）操作长桥。

目前只能连接**模拟账户**。设计上已为实盘账户预留（见[实盘交易](#实盘交易未开启)），但本版本没有任何开启方式。

## 工作方式

```
 调度器 ─▶ 计划生成 ─▶ 交易计划（复核窗口、人工确认）─▶ 执行
              ▲                                         │
              │ 现金、持仓                        订单   ▼
          账户同步 ◀──── longbridge serve（标准输入输出上的 JSON-RPC）────▶ 长桥模拟账户
              ▲                                         │
              └──────────── 成交、订单状态 ◀────────────┘
```

- **通信方式。** hone-quant 运行 `longbridge serve`——客户端为其他软件提供的接口：通过标准输入输出传输 JSON-RPC 2.0，内容是长桥 OpenAPI 的原始数据（精确小数、字段与官方文档一致）。客户端的 `--format json` 输出是为人和 AI 整理过的格式，可能随版本变化，因此不用于交易。另外只用到两个一次性命令：`longbridge --version` 和 `longbridge auth status`（当前登录的账户）。解析代码在 `crates/quant-server/src/brokers/longbridge/wire.rs`，测试使用的数据在 `crates/quant-server/tests/fixtures/longbridge/`。
- **登录。** 客户端自己保存 OAuth 令牌（加密并绑定本机），位于 `$HOME/.longbridge`；hone-quant 不接触长桥的任何凭据。服务器只需登录一次（见[配置步骤](#配置步骤)），令牌会自动续期。
- **连接组合。** 新建组合时选择「交易执行：长桥模拟账户」（仅管理员）会读取该账户：美元现金，以及其中属于投资范围的美股持仓（按券商成本价接管）。初始资金为现金加上这些持仓的市值。其他市场或投资范围之外的持仓标记为「不由本组合管理」，只显示、不交易。一个长桥账户只能连接一个使用中的组合。
- **生成计划。** 生成计划前先同步账户，计划按券商的实际现金和持仓计算。
- **执行。** 计划执行时（复核窗口结束后自动执行，或人工确认后）：
  1. 同步并核对账户（仍是同一个长桥账户，并且是模拟账户）；
  2. 与模拟撮合相同的报价检查（报价新鲜、价格在计划容差内）；
  3. **先卖后买**：所有卖单结束后（最多等待十分钟）再下买单，买单按长桥报告的可用美元现金确定数量；
  4. 每笔订单都是**当日有效的限价单、整股、仅常规交易时段**，价格比当前报价让 1%，但不超出计划的价格容差（设置 → 执行与成本中的 `max_price_deviation`）。这样可以按市价成交，又不会在行情骤变时远离计划价格成交。策略给出的零股数量向下取整。
  5. 每笔订单带有备注 `hq-<订单编号>`，在长桥 App 中可见。
- **跟踪订单。** 调度器每 15 秒读取一次券商的订单和成交。每笔成交记一次（按券商成交编号去重），持仓和现金的变化与模拟成交完全相同。订单结束时，从订单的费用明细中读取佣金和其他费用，记在该订单最后一笔成交上。计划截止时间（收盘前 5 分钟）仍未结束的订单会被撤销。所有订单结束后，计划按实际结果结束（已执行、部分执行或失败），并同步、通知。
- **账户同步。** 以券商为准。开盘前、交易时段内每五分钟、每次生成计划前、每次计划结束后、收盘快照前，以及手动点击（设置 → 账户 →「立即同步」）时，都会与长桥核对。任何差异（分红、费用、出入金、在长桥 App 中的交易）都记为调整，并写入审计日志（`account.synchronised`）。有订单在券商处理时暂不核对，避免把尚未读回的成交误认为差异。现金取美元的可用加冻结金额（与客户端自己的资产视图一致）。
- **人工干预。** 确认、取消、移除订单与以前相同。正在券商执行的计划可以在计划页面**停止执行**：撤销券商端未完成的订单，不再发送尚未发出的订单，计划按已成交部分结束。连接长桥的组合不能重置（账目以券商为准），需要重新开始时请归档。
- **异常情况。** 无法连接长桥、客户端未登录、或登录的是另一个（或实盘）账户时，不会进行任何交易：计划生成和执行会失败并说明原因，设置 → 账户中显示错误，组合也会收到通知（每小时最多一次）。提交结果不确定的订单（例如超时）会先按备注、再按代码、方向、数量和价格查找，绝不会重复发送。

## 安全措施

- **只限模拟盘，由长桥强制执行。** 客户端运行时设置 `LONGBRIDGE_PAPERTRADING=true`，长桥 SDK 会把每个交易请求标记为模拟交易，如果登录的是实盘账户，长桥服务器会拒绝请求。此外，hone-quant 还会核对 `auth status` 和持仓中报告的账户渠道（`lb_papertrading`），数据库也不允许模拟撮合的账户设为实盘。
- **两步下单。** 客户端不会在第一次请求时下单或撤单，而是返回预览和确认码。hone-quant 核对预览与要下的订单完全一致（代码、方向、数量、价格、订单类型）后，才发送确认码。
- **账户一致。** 组合记录了连接的账户；如果之后客户端登录了另一个账户，同步和交易会报错停止，而不会接管另一个账户的账目。
- **限速与隔离。** 调用依次进行（并发刷新令牌会冲突），间隔一秒，低于长桥交易接口每 30 秒 30 次的限制。客户端在空的工作目录中运行（其 SDK 会读取当前目录的 `.env`），关闭统计上报（`DO_NOT_TRACK=1`）；`serve` 会话空闲十分钟后停止。

## 配置步骤

1. **在运行 hone-quant 的主机上安装客户端。** 建议固定版本，不要直接运行安装脚本。Linux x86-64 例如：

   ```bash
   curl -fsSL -o /tmp/lb.tgz \
     https://github.com/longbridge/longbridge-terminal/releases/download/v0.30.0/longbridge-terminal-linux-musl-amd64.tar.gz
   sudo tar -xzf /tmp/lb.tgz -C /usr/local/bin longbridge
   longbridge --version
   ```

   如果不在服务的 `PATH` 中，设置 `HONE_QUANT_LONGBRIDGE_BIN=/path/to/longbridge`。

2. **在长桥开发者平台（open.longbridge.com）开通模拟账户。** 模拟账户在长桥的 AP 数据中心（香港/新加坡账户）提供。请确保账户中有美元现金。

3. **让服务器登录长桥。** 以服务用户、使用服务的环境登录，令牌才会保存在服务器读取的位置（令牌与机器绑定，必须在服务器上操作）：

   ```bash
   sudo /opt/hone-quant/current/scripts/hq.sh longbridge auth login   # 设备授权：打开链接并确认
   sudo /opt/hone-quant/current/scripts/hq.sh longbridge               # 检查：客户端、登录、账户、现金、持仓
   ```

   `hone-quant longbridge <参数>` 以与服务器完全相同的方式运行客户端（相同的主目录，开启模拟盘保护）。在授权页面上选择**模拟账户**。本地开发：`cargo run -p quant-server -- longbridge auth login`。

4. **连接组合。** 组合 → 新建组合 → 交易执行：「长桥模拟账户」。对话框会显示连接是否可用、连接的是哪个账户。之后在设置 → 账户中可以看到券商同步面板：上次同步时间、现金明细、调整记录、不由本组合管理的持仓，以及「立即同步」。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HONE_QUANT_LONGBRIDGE_BIN` | `PATH` 中的 `longbridge` | 客户端可执行文件 |
| `HONE_QUANT_LONGBRIDGE_HOME` | 服务的 `HOME` | 客户端使用的 `HOME`，即登录信息所在位置（`$HOME/.longbridge`） |

在 GCE 部署中，服务用户的主目录是 `/var/lib/hone-quant`，systemd 允许写入；客户端安装在 `/usr/local/bin` 时，两个变量都不需要设置。Docker 镜像中不包含客户端。

## 限制

- 仅美股、美元、常规交易时段、当日限价单、整股。
- 仅长桥 AP 数据中心的模拟账户。美国数据中心的账户使用 `longbridge serve` 不支持的接口，会被明确拒绝。
- 客户端不推送订单更新，成交通过轮询读回（有订单在处理时每 15 秒一次）。
- 分红、费用以及在 hone-quant 之外的操作通过同步调整入账，不会逐笔生成资金流水。
- 绩效从连接日起计算，起始净值为接管时的现金和持仓。

## 实盘交易（未开启）

这套接入的设计让开启实盘只需改变策略，而不必重写：账户带有 `mode`（`paper`/`live`），数据库只允许券商账户为 `live`，券商客户端按券商和模式分别注册，账户核对也是双向的（实盘客户端必须看到非模拟渠道）。刻意没有提供的部分：没有注册实盘客户端（`main.rs` 只注册模拟盘客户端），连接时拒绝 `mode: live`，界面也只提供模拟盘。若要开启，至少需要：单独登录实盘账户的 `HOME`、不带模拟盘保护的实盘客户端、操作员明确的开启操作、额外的交易前限额（单笔金额上限、每日换手），以及完整的端到端审查。
